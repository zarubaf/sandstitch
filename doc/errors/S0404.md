# S0404: conflicting connection intent

The same bits are given intents that exclude each other. On one end's bits: marked unused and also connected, tied off or given a net name; marked unused twice with different ranges; tied off twice. Within one component (bits joined by connections): two net names, a tieoff and a net name, or a net name on a component driven by a definition input, whose net is the input port itself. A tieoff and a connection on one end are not a conflict of intent; a tieoff then drives the component, and with another driver that is S0401. Repeating a call exactly (the same ends, ranges and values) is not reported. `ModDef::check` reports one conflict per component, about the end the latest of the two calls was made on, with that call as the primary label; `emit` panics with it.

## Example

`blocks.sv`:

```systemverilog
module src(output logic [7:0] o); endmodule
module snk(input logic [7:0] i); endmodule
```

With `cfg` listing that source:

```rust
let src = ModDef::from_verilog_with_config("src", &cfg);
let snk = ModDef::from_verilog_with_config("snk", &cfg);
let top = ModDef::new("top");
let a = top.instantiate(&src, Some("a"), None);
let u = top.instantiate(&snk, Some("u"), None);
a.get_port("o").connect(&u.get_port("i"));
a.get_port("o").slice(3, 0).unused();
let diagnostics = top.check();
```

```text
error[S0404]: conflicting intent on `top.a.o[3:0]`: marked unused and connected
 --> src/main.rs:7:29
  |
6 | a.get_port("o").connect(&u.get_port("i"));
  |                 ------- connected here
7 | a.get_port("o").slice(3, 0).unused();
  |                             ^^^^^^ marked unused here
```

## Fix

Give each bit one intent: remove the `unused` mark from connected bits, the second tieoff, or one of the net names.
