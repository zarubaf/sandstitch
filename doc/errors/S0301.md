# S0301: module defined twice in the build

An imported module is emitted from the model (re-emitted with `Usage::EmitDefinitionAndDescend` or stubbed with `Usage::EmitStubAndStop`), but the file that defines it is also a manifest source because other modules imported from it are not emitted. Building the emitted RTL with the manifest sources would define the module twice. `ModDef::try_manifest` returns the diagnostic; `ModDef::manifest` panics with it rendered.

The defining file is found from the module's port declarations, so a module without ports is not checked.

## Example

`/work/blocks.sv`:

```systemverilog
module producer (output logic [7:0] data_o); endmodule
module consumer (input logic [7:0] data_i); endmodule
```

```rust
let producer = ModDef::from_verilog_with_config("producer", &cfg);
let consumer = ModDef::from_verilog_with_config("consumer", &cfg);
consumer.set_usage(Usage::EmitStubAndStop);
let top = ModDef::new("top");
let p = top.instantiate(&producer, Some("p"), None);
let c = top.instantiate(&consumer, Some("c"), None);
p.get_port("data_o").connect(&c.get_port("data_i"));
top.manifest();
```

```text
error[S0301]: module `consumer` would be defined twice: by the emitted RTL and by `/work/blocks.sv`
 --> /work/blocks.sv:2:36
  |
2 | module consumer (input logic [7:0] data_i); endmodule
  |                                    ^ `consumer` is defined in this listed source
  |
  = note: `consumer` is emitted from the model, and `/work/blocks.sv` is listed for other modules
  = help: move the module into its own file, or emit nothing for it (`Usage::EmitNothingAndStop`) and build with its source
```

## Fix

Put modules that are emitted from the model in files of their own, so the manifest does not list them, or keep their usage at `Usage::EmitNothingAndStop` and build with the original source.
