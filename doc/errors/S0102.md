# S0102: Slang elaboration error

Slang rejected the source while elaborating one specialization. Each error Slang reported is a label at its SystemVerilog span (the first is the primary label); Slang's output is a note when it has no location. All Slang errors for that specialization are reported together. For `try_parameterize` and `try_from_verilog_parameterized`, the primary label is the Rust call site; errors in the generated elaboration top (an unknown type or constant in an override) are notes naming the override, and the note `elaborated as ...` shows the instantiation Slang saw.

A specialization reports this code before running Slang when the import configuration's extra arguments contain `--Mall`: specialization passes `--Mall` itself to list the files it reads (for its cache key), and Slang accepts it once. It also reports it when the temporary elaboration files cannot be written or Slang writes no dependency list.

The same code is reported when the sources elaborate but the requested module is not a top-level module of the elaborated design: it is not defined, or another module instantiates it and no `tops` were given.

## Example

```systemverilog
module router (input cfg_pkg::flit_t flit_i); endmodule   // no source defines `cfg_pkg`
```

With `cfg` listing that source:

```rust
ModDef::try_from_verilog_with_config("router", &cfg)?;
```

Other causes: a type parameter that defaults to `logic` but is used as a struct, or importing a module that another module in the sources instantiates.

## Fix

Fix the SystemVerilog error shown in the snippet (missing source, undefined identifier, bad parameter value) and re-run. A module that does not elaborate with its default parameters can be imported directly with overrides that make it elaborate: `ModDef::try_from_verilog_parameterized("m", &cfg, &[("T", ParameterValue::Type("pkg::t".into()))])`. For a module that is not a top, add its source or select it with `tops: &["leaf"]` in the `ParserConfig`.
