# S0403: undriven net

A component (bits joined by connections inside one definition) needs a driver: a definition input, an instance output, a tieoff on one of its ends, or inouts. Connections are made only between ends that can drive and ends that receive, or with inouts, so a component without a driver is one whose ends only receive: for example an instance input that is only given a net name (`specify_net_name`). Components whose every bit is marked unused are not reported here; unused on an end that receives is S0405. `ModDef::check` reports the component once, about its first end in declaration order, with at most three notes about ends on it and a note counting the rest ("… and N more"); `emit` panics with it.

## Example

`snk.sv`:

```systemverilog
module snk(input logic [7:0] i); endmodule
```

With `cfg` listing that source:

```rust
let snk = ModDef::from_verilog_with_config("snk", &cfg);
let top = ModDef::new("top");
let u = top.instantiate(&snk, Some("u"), None);
u.get_port("i").specify_net_name("data");
let diagnostics = top.check();
```

```text
error[S0403]: `top.u.i` has no driver
 --> src/main.rs:4:17
  |
4 | u.get_port("i").specify_net_name("data");
  |                 ^^^^^^^^^^^^^^^^ net named here
  |
  = note: `top.u.i` is on this net
```

## Fix

Connect the bits to a definition input or an instance output, or tie them off.
