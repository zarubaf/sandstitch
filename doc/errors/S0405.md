# S0405: tieoff or unused on the wrong direction

A tieoff drives bits, so it applies only to ends that receive inside the definition: definition outputs, instance inputs and inouts. Marking bits unused says nothing reads them, so it applies only to ends that drive inside the definition: definition inputs, instance outputs and inouts. `ModDef::check` reports a tieoff on a definition input or an instance output, and an unused mark on a definition output or an instance input, with the call as the label; `emit` panics with it.

## Example

`src.sv`:

```systemverilog
module src(output logic [7:0] o); endmodule
```

With `cfg` listing that source:

```rust
let src = ModDef::from_verilog_with_config("src", &cfg);
let top = ModDef::new("top");
let a = top.instantiate(&src, Some("a"), None);
a.get_port("o").tieoff(0);
let diagnostics = top.check();
```

```text
error[S0405]: `top.a.o` cannot be tied off: it is an instance output
 --> src/main.rs:4:17
  |
4 | a.get_port("o").tieoff(0);
  |                 ^^^^^^ tied off here
```

## Fix

Mark bits that drive and are not read as unused, and tie off bits that receive; `unused_or_tieoff` picks the one the port's direction allows.
