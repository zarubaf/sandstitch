# S0105: unsupported override expression

Type and value overrides accept only `ident` or `pkg::ident`, naming a type or constant. The same code covers an override of the wrong kind (a type for a value parameter, or a value for a type parameter), an integer that does not fit its parameter's type, a negative integer, and a string with characters other than printable ASCII (or with quotes or backslashes). The import configuration's Slang `-G` values (`ParserConfig::parameters`) of parameters the module declares are emitted as overrides of its instances, for a plain import too, and apply to every specialization. So each must be a decimal integer, a string literal or a name, and set a value parameter. The code is reported for any other value (`8'hff`, `1+1`), a type parameter, or a name set twice (Slang would apply the first): at import for a plain import, at specialization unless an explicit override of that parameter replaces it. `-G` values of parameters the module does not declare are ignored, as by Slang.

A bare `ident` refers to the generated elaboration top's compilation unit, so it resolves only with `--single-unit` in the configuration's extra arguments; prefer `pkg::ident`.

## Example

```rust
router.try_parameterize(&[("flit_t", ParameterValue::Type("struct packed { logic a; }".into()))])?;
```

## Fix

Define a named type in a package and override with `ParameterValue::Type("cfg_pkg::flit_t".into())`.
