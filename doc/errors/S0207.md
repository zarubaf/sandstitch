# S0207: member without a partner

`Intf::connect` pairs each member with the same-named member of the other interface that is driven the other way: an output with an input between instances, ports of the same direction between a module and its instance. A member with no such partner is reported, at the call site, unless `allow_mismatch` is `true`.

## Example

`node.sv`:

```systemverilog
package node_pkg;
  typedef struct packed { logic valid; logic [7:0] data; } req_t;
  typedef struct packed { logic ready; logic [3:0] code; } rsp_t;
endpackage
module node import node_pkg::*; (
  input req_t [1:0] req_i, output req_t [1:0] req_o,
  input rsp_t [1:0] rsp_i, output rsp_t [1:0] rsp_o
);
endmodule
```

With `cfg` listing that source:

```rust
let node = ModDef::from_verilog_with_config("node", &cfg);
node.def_intf_members("link", [("req", node.get_port("req_o").index(0)), ("req", node.get_port("req_i").index(0)), ("rsp", node.get_port("rsp_o").index(0))]);
let top = ModDef::new("top");
let a = top.instantiate(&node, Some("a"), None);
let b = top.instantiate(&node, Some("b"), None);
a.get_intf("link").connect(&b.get_intf("link"), false);
```

```text
error[S0207]: member `rsp` of `top.a.link` has no partner in `top.b.link`
 --> src/main.rs:6:20
  |
6 | a.get_intf("link").connect(&b.get_intf("link"), false);
  |                    ^^^^^^^ interfaces connected here
  |
  = note: `top.a.rsp_o[0]` (output) needs a member `rsp` driven the other way
  = help: pass `allow_mismatch = true` to leave unpaired members unconnected
```

## Fix

Give both interfaces the same members in both directions (add `("rsp", node.get_port("rsp_i").index(0))`), or pass `allow_mismatch = true` to leave unpaired members unconnected.
