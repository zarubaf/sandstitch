# S0201: incompatible types

Both ends of a connection have aggregate types (structs, unions or enums, as whole typed ports or as fields and elements selected with `field`/`index`), and their types are not structurally equivalent; equal width is not enough. If either end is a plain logic vector, only widths are compared, as upstream. Type names do not matter: two differently named types with the same layout connect fine. `ModDef::check` reports the violation with the `connect` call site as the primary label, the declarations of both ports as secondary labels, and the first difference as a note; `emit` panics with it.

## Example

```systemverilog
package bus_pkg;
  typedef struct packed { logic [31:0] addr; logic [7:0] id; } req_t;
  typedef struct packed { logic [7:0] id; logic [31:0] addr; } req2_t;
endpackage
module producer import bus_pkg::*; (output req_t req_o); endmodule
module consumer import bus_pkg::*; (input req2_t req_i); endmodule
```

With `cfg` listing that source:

```rust
let producer = ModDef::from_verilog_with_config("producer", &cfg);
let consumer = ModDef::from_verilog_with_config("consumer", &cfg);
let top = ModDef::new("top");
let p = top.instantiate(&producer, Some("p"), None);
let c = top.instantiate(&consumer, Some("c"), None);
p.get_port("req_o").connect(&c.get_port("req_i"));   // both 40 bits wide
let diagnostics = top.check();
```

## Fix

Connect ends of equivalent types, for example by selecting matching fields with `field`. To reinterpret the bits deliberately, use `connect_bits`, which checks the width only and records the connection as intentional.
