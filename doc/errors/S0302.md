# S0302: macro defined differently in the build

The manifest lists the macro definitions (`ParserConfig::defines`) of every import whose sources it lists, since the emitted RTL is built with those sources and one set of definitions. Two such imports define the same macro with different values, so no single build matches both imports. `ModDef::try_manifest` returns the diagnostic; `ModDef::manifest` panics with it rendered.

## Example

`narrow.sv` and `wide.sv`, whose paths are `narrow_sv` and `wide_sv`:

```systemverilog
module narrow (input logic [`WIDTH-1:0] a); endmodule
```

```systemverilog
module wide (input logic [`WIDTH-1:0] b); endmodule
```

```rust
let narrow = ModDef::from_verilog_with_config("narrow", &ParserConfig {
    sources: &[narrow_sv],
    defines: &[("WIDTH", "8")],
    ..Default::default()
});
let wide = ModDef::from_verilog_with_config("wide", &ParserConfig {
    sources: &[wide_sv],
    defines: &[("WIDTH", "16")],
    ..Default::default()
});
let top = ModDef::new("top");
top.instantiate(&narrow, Some("n"), None);
top.instantiate(&wide, Some("w"), None);
top.manifest();
```

```text
error[S0302]: macro `WIDTH` is defined as `8` for `narrow` and as `16` for `wide`
  |
  = note: `wide` was imported with `WIDTH=16`
  = note: `narrow` was imported with `WIDTH=8`; the emitted RTL is built with one set of definitions
  = help: import the modules with the same definition, or rename the macro in one of them
```

## Fix

Import the modules with the same definition, or rename the macro in one of the sources. A value that differs per module is usually a parameter: override it with `try_parameterize` instead.
