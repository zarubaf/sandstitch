# S0209: name-based operation on a member in both directions

An interface with a name in both directions (`req` output and `req` input) can be connected, exported, tied off and read with `members`. Operations that identify members by name only cannot tell the two apart: `get`, `remove`, `iter`, `keys`, `values`, `width`, `connect_pipeline`, `connect_through`, `crossover`, `subdivide`, `copy_to`, `flip_to`, `feedthrough` and `todo_jam_connect`; the physical-design operations `set_max_distance`, `block_tracks`, `place_across`, `place_across_from`, `place_abutted`, `place_overlapped` and `place_crossover_from`; and `Funnel::connect_intf` and `Funnel::crossover_intf`. They are reported at the call site.

## Example

`node.sv`:

```systemverilog
package node_pkg;
  typedef struct packed { logic valid; logic [7:0] data; } req_t;
  typedef struct packed { logic ready; logic [3:0] code; } rsp_t;
endpackage
module node import node_pkg::*; (
  input req_t [1:0] req_i, output req_t [1:0] req_o,
  input rsp_t [1:0] rsp_i, output rsp_t [1:0] rsp_o
);
endmodule
```

With `cfg` listing that source:

```rust
let node = ModDef::from_verilog_with_config("node", &cfg);
let link = node.def_intf_members("link", [("req", node.get_port("req_o").index(0)), ("req", node.get_port("req_i").index(0))]);
link.get("req");
```

```text
error[S0209]: interface `node.link` has member `req` in both directions
 --> src/main.rs:3:6
  |
3 | link.get("req");
  |      ^^^ used here
  |
  = note: a name present in both directions does not identify one member
  = help: use `connect`, `export_with_prefix`, `tieoff`, `unused` or `members`, which tell the directions apart
```

## Fix

Read the members with `members()`, which lists each with its slice and hence its direction, or use an interface whose names are unique.
