# S0303: emitted module needs a package the manifest cannot list

The emitted RTL uses a package: a port or net declared with a struct or union type from it, an enum cast to one of its types, a type or constant override naming it, or a field or element of such a type. The manifest lists the sources of an import that declares the package. An import whose module is descended into has all its sources listed anyway. An import whose module is emitted from the model (re-emitted with `Usage::EmitDefinitionAndDescend` or stubbed with `Usage::EmitStubAndStop`) has its sources listed only when the package needs it, and then without the files defining emitted modules, whose definitions would clash with the emitted ones, but with its include directories, libraries and definitions. The manifest reports S0303 when it cannot list the package:

- ``package `{p}` needed by emitted module `{m}` is declared in the module's own file `{f}` ``: the package is declared in a file defining an emitted module;
- ``package `{p}` of the import listed for `{needed}` is declared in `{f}`, which defines emitted module `{m}` ``: an emitted import is listed for the needed package `{needed}`, and another package of that import is declared in a file defining an emitted module. It is reported whether or not a listed file uses that package, since the manifest cannot tell;
- ``package `{p}` needed by emitted module `{m}` is declared in `{f}`, which is not a source or library of its import``, or, when the import's module is descended into, ``package `{p}` used by the emitted RTL is declared in `{f}`, which is not a source or library of the import of `{m}` ``: for example, a file passed through `ParserConfig::extra_arguments`;
- ``the file defining emitted module `{m}` is not a source of its import, so the packages it needs cannot be listed``: for example, the module's first port is declared in an `include`d file, or the module comes from a library;
- ``package `{p}` used by the emitted RTL is declared by no import of the design``: for example, it is declared only in text passed to `ModDef::from_verilog`. Such text lives in a temporary file deleted after import, so the manifest lists neither its sources nor its packages.

`ModDef::try_manifest` returns the diagnostic; `ModDef::manifest` panics with it rendered. The defining file is taken to be the file of the module's first port declaration that has an SV span, as for [S0301](S0301.md). A package in an `include`d file belongs to the file including it.

## Example

`/work/regs.sv`:

```systemverilog
package regs_pkg;
  typedef struct packed { logic valid; logic [7:0] data; } req_t;
endpackage
module regs (input regs_pkg::req_t req_i); endmodule
```

With `cfg` listing that file:

```rust
let regs = ModDef::from_verilog_with_config("regs", &cfg);
regs.set_usage(Usage::EmitStubAndStop);
let top = ModDef::new("top");
let r = top.instantiate(&regs, Some("r"), None);
r.get_port("req_i").tieoff(0);
top.manifest();
```

```text
error[S0303]: package `regs_pkg` needed by emitted module `regs` is declared in the module's own file `/work/regs.sv`
 --> /work/regs.sv:4:36
  |
4 | module regs (input regs_pkg::req_t req_i); endmodule
  |                                    ^^^^^ `req_i` is declared with a type from `regs_pkg`
  |
  = note: `regs` is emitted from the model, so the manifest leaves out its file, and `regs_pkg` with it
  = help: declare the package in a file of its own and list it among the import's sources
```

## Fix

Declare the package in a file of its own and list it among the import's sources, before the files that use it. For a module whose first port is declared in an `include`d file, declare a port in the module's own file first, or keep the module's usage at `Usage::EmitNothingAndStop` and build with its source.
