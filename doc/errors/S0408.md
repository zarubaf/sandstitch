# S0408: different definitions with one key

Two different definitions are reachable from the design under one key: the same module name and the same parameter overrides. A key names one definition, so the design cannot hold both. Definitions are compared when they are not the same `ModDef`; equal ones are one definition and are emitted once, different ones are this error. The message names the first field that differs, in the order usage, ports, parameter overrides, instances, interfaces, connections. A definition that is only a stub is compared on usage, ports (name, direction, width, type, enum cast) and parameter overrides alone; connections are compared only for definitions that are emitted with their contents. A definition with connection errors is not compared on its connections, and its errors are reported. An emitted definition and another definition with a different key but the same module name, such as two specializations of one module both emitted as stubs, are reported the same way, with the help to emit a renamed copy of one with `ModDef::stub(name)`.

`ModDef::check` reports it once per later definition (each is compared with the first of its key), with a note naming the instance path that uses each definition; `emit` panics with it.

## Example

```rust
let first = ModDef::new("leaf");
first.add_port("i", IO::Input(1)).unused();
let second = ModDef::new("leaf");
second.add_port("i", IO::Input(2)).unused();
let top = ModDef::new("top");
top.instantiate(&first, Some("a"), None).get_port("i").tieoff(0);
top.instantiate(&second, Some("b"), None).get_port("i").tieoff(0);
let diagnostics = top.check();
```

```text
error[S0408]: two different definitions `leaf`: they differ in ports
 --> src/main.rs:3:14
  |
1 | let first = ModDef::new("leaf");
  |             ------ first defined here
2 | first.add_port("i", IO::Input(1)).unused();
3 | let second = ModDef::new("leaf");
  |              ^^^^^^ defined here
  |
  = note: used at a
  = note: used at b
  = help: give one of the definitions another name
```

## Fix

Give one of the definitions another name. Two specializations of one module that are both emitted therefore need distinct names: `ModDef::stub(name)` makes a parameter-free renamed copy of each, which a parent instantiates without overrides. A generator that builds the same module with different contents must name each configuration, for example `adder8` and `adder16`; the library never renames a definition.
