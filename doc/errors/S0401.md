# S0401: multiple drivers

Bits joined by connections inside one definition form a component, and a component has exactly one driver: a definition input, an instance output, a constant (a tieoff on any of its ends), or, when it has none of these, its inouts together. A component with more than one driver is an error: two definition inputs or instance outputs, one of each, a tieoff and a port, or tieoffs on two of its ends. Drivers are counted per bit lane: two bits of one definition input or instance output joined into one component are two drivers, and so are two bits of one end that a tieoff covers. Several tieoffs on the same bits of one end are S0404, not more drivers, and a tieoff on an end that may not be tied off is S0405 and does not count. `ModDef::check` reports the component once, about its first end in declaration order, with a note per driver, the latest connection involved as the primary label and the others as secondary labels; `emit` panics with it.

## Example

`blocks.sv`:

```systemverilog
module src(output logic [7:0] o); endmodule
module snk(input logic [7:0] i); endmodule
```

With `cfg` listing that source:

```rust
let src = ModDef::from_verilog_with_config("src", &cfg);
let snk = ModDef::from_verilog_with_config("snk", &cfg);
let top = ModDef::new("top");
let u = top.instantiate(&snk, Some("u"), None);
let a = top.instantiate(&src, Some("a"), None);
let b = top.instantiate(&src, Some("b"), None);
a.get_port("o").connect(&u.get_port("i"));
b.get_port("o").connect(&u.get_port("i"));
let diagnostics = top.check();
```

```text
error[S0401]: `top.u.i` has more than one driver
 --> src/main.rs:8:17
  |
7 | a.get_port("o").connect(&u.get_port("i"));
  |                 ------- connected here
8 | b.get_port("o").connect(&u.get_port("i"));
  |                 ^^^^^^^ connected here
  |
  = note: driven by `top.a.o`
  = note: driven by `top.b.o`
```

## Fix

Drive each component from one source: remove the extra connection or tieoff, or connect the drivers to different sinks.
