# S0407: net name collision

The emitted module would declare two different nets under one name. A definition port is a net named after the port, a connected instance port is a net named `<instance>_<port>`, and `specify_net_name` names a net as given; two different sources of these that produce the same string cannot be told apart in the emitted module. A source that no connection uses as a net does not count: when `specify_net_name` renames a net, the instance port it replaces does not take its name. `ModDef::check` reports the later net of each collision, about the whole port it is named after (for a named net, the instance port `specify_net_name` was called on); `emit` panics with it.

## Example

`blocks.sv`:

```systemverilog
module src(output logic [7:0] o); endmodule
module snk(input logic [7:0] i); endmodule
```

With `cfg` listing that source:

```rust
let src = ModDef::from_verilog_with_config("src", &cfg);
let snk = ModDef::from_verilog_with_config("snk", &cfg);
let top = ModDef::new("top");
top.add_port("data", IO::Input(8)).unused();
let a = top.instantiate(&src, Some("a"), None);
let u = top.instantiate(&snk, Some("u"), None);
a.get_port("o").connect(&u.get_port("i"));
a.get_port("o").specify_net_name("data");
let diagnostics = top.check();
```

```text
error[S0407]: net name `data` is used by both definition port `data` and net name `data`
 --> src/main.rs:9:15
  |
9 | a.get_port("o").specify_net_name("data");
  |                 ^^^^^^^^^^^^^^^^ net named here
  |
  = help: rename a port, or give one of the nets another name with `specify_net_name`
```

## Fix

Rename the definition port, the instance or the instance port, or give one of the nets another name with `specify_net_name`.
