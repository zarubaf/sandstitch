# SystemVerilog packages

## Goal

Designs and generators get the SystemVerilog packages they need from the model, never from hand-written text. A `PackageDef` is built in Rust, emitted by xlsynth-vast, written under a content-hashed name, and passed to imports like any other source. Parameter overrides name its members through the package, not through strings.

## Decisions

1. **The model builds, vast emits.** `PackageDef` holds typed members. Emission lowers them to xlsynth-vast, which gains a `package` file item. No member takes free SystemVerilog text.
2. **Members.** A package holds:
   - `include` lines, emitted before the `package` line;
   - localparams of a declared type (the issue's "type values" are these typed localparams);
   - typedefs of logic vectors, packed structs and enums;
   - invocations of macros at package scope, for example an upstream typedef macro.

   A macro's arguments are names (`ident`, `pkg::ident`, or the keyword `logic`) or unsigned integers. The caller lists the names a macro declares, so handles can refer to them.
3. **Values are computed in Rust.** A localparam's value is an integer, a name (`ident` or `pkg::ident`, for an enum value or another constant), or an assignment pattern of named fields (`'{Width: 48, ...}`). Derived values, such as a count that depends on another setting, are computed in Rust and emitted as constants. There is no expression language.
4. **Files are content-addressed.** `PackageDef::write(dir)` writes `<name>-<hash>.sv`, where the hash is the first 12 hex digits of the SHA-256 of the emitted text. It writes atomically (a temp file, then a rename) and returns the path. The path goes into an import's sources, so the build manifest lists it like any source of a descended import.
5. **Handles, not strings.** `PackageDef::ty(name)` and `PackageDef::constant(name)` return `ParameterValue::Type` and `ParameterValue::Expr` for `<package>::<name>`, and panic when the package declares no such type or constant. Typedefs and macro-declared names are types. Localparams and enum variants are constants.
6. **Scope.** Signed types and negative values are out of scope. The structural snapshot shows package members once it exists (#45).

## API

```rust
pub struct PackageDef { /* name, includes, members */ }

pub enum PackageType {
    IntUnsigned,               // int unsigned
    Logic(usize),              // logic [w-1:0]; width 1 is logic [0:0]
    Named(String),             // ident or pkg::ident
}

pub enum PackageValue {
    Int(u32),
    Name(String),                        // ident or pkg::ident
    Fields(Vec<(String, PackageValue)>), // '{Name: value, ...}
}

impl PackageDef {
    pub fn new(name: &str) -> PackageDef;
    pub fn include(&mut self, path: &str) -> &mut Self;
    pub fn localparam(&mut self, name: &str, ty: PackageType, value: PackageValue) -> &mut Self;
    pub fn typedef_logic(&mut self, name: &str, width: usize) -> &mut Self;
    pub fn typedef_struct(&mut self, name: &str, fields: &[(&str, PackageType)]) -> &mut Self;
    pub fn typedef_enum(&mut self, name: &str, width: usize, variants: &[(&str, u32)]) -> &mut Self;
    pub fn macro_call(&mut self, name: &str, args: &[&str], declares: &[&str]) -> &mut Self;
    pub fn ty(&self, name: &str) -> ParameterValue;
    pub fn constant(&self, name: &str) -> ParameterValue;
    pub fn emit(&self) -> String;
    pub fn write(&self, dir: &Path) -> std::io::Result<PathBuf>;
}
```

The builder panics, naming the package and the member, on any of these:
- a package, member, field, variant or macro name that is not an `ident`;
- a name declared twice in the package (typedefs, localparams, enum variants and macro-declared names share one namespace);
- a struct field named twice;
- an empty struct or enum;
- a width of 0;
- an enum variant value that does not fit its width;
- two enum variants with one value;
- an `Int` that does not fit its type (`Logic(w)` holds values below 2^w);
- an include path that is empty or contains `"` or a line break;
- a macro argument that is neither a name nor an unsigned integer without leading zeros;
- an assignment pattern with no fields, a repeated field, or one given to a type that is not `Named`.

Names are checked against the identifier syntax only; a SystemVerilog keyword used as a name is reported by Slang.

Values under a `Named` type (field values, or an `Int` given a named type) are not checked against that type; Slang reports a mismatch.

`ty` and `constant` report the caller's location. Members are emitted in the order they were added. A packed struct lists its fields MSB first, as in SystemVerilog.

## Emitted form

```systemverilog
// Generated by sandstitch. Do not edit.
`include "ext/typedef.svh"

package cfg_pkg;
  localparam ext_pkg::cfg_t Cfg = '{Width: 48, Depth: 4};
  localparam int unsigned Count = 1;
  typedef logic [1:0] x_bits_t;
  typedef struct packed {
    logic [1:0] x;
    logic [1:0] y;
  } xy_t;
  typedef enum logic [1:0] {
    A = 0,
    B = 1
  } dir_e;
  localparam xy_t Origin = '{x: 1, y: 0};
  localparam dir_e Start = B;
  `TYPEDEF_HDR_T(hdr_t, xy_t, logic, 2)
endpackage
```

The text is deterministic, so the hash is stable. Integers are emitted in decimal: unsized up to 2^31 − 1, and as `32'd…` above that.

## Limits

A package reaches the build manifest only as a source of an import the manifest walk descends into. An import emitted as a stub whose ports use package types does not bring its sources into the manifest (#56).

## Testing

- xlsynth-vast: the emitted form above, item by item, in `crates/xlsynth-vast/tests/sandstitch_ext_test.rs`.
- `PackageDef`:
  - the emitted form above;
  - one test per rejected input;
  - `ty` and `constant` for each kind of declared name;
  - `write` returning the same path and identical bytes on a second call.
- Slang: a package with every member kind except a macro, imported with a module whose type parameter is overridden through `PackageDef::ty`, elaborates from the manifest. Its localparams read back through `extract_packages_from_verilog_file`.
- FlooNoC: its configuration package is a `PackageDef`, and the mesh tests still elaborate.
